Netzwerk-Praxisprojekt: Das Nimm-Spiel

Implementierung eines rundenbasierten 2-Spieler-Netzwerkspiels mit Socket-Kommunikation, Zustandsverwaltung und den Abiturklassen des Landes NRW.

1

Das Spielprinzip (Misère-Variante)

Das Nimm-Spiel ist ein klassisches mathematisches Strategiespiel für zwei Personen. Für unser Netzwerkprojekt gelten folgende verbindliche Rahmenbedingungen:

MERKE
Die offiziellen Spielregeln für das Projekt:
• Startbestand: Es liegen genau $n = 17$ Objekte (z. B. Hölzchen oder Spielsteine) auf dem Tisch.
• Spieleranzahl: Genau $2$ Spieler treten gegeneinander an (Spieler 1 beginnt).
• Zulässige Züge: Wer an der Reihe ist, muss mindestens $1$ und darf höchstens $3$ Objekte nehmen ($k \in \{1, 2, 3\}$).
• Misère-Endbedingung: Wer gezwungen ist, das letzte verbleibende Objekt zu nehmen, hat das Spiel verloren. Der Gegenspieler gewinnt.

Warum ein Spielserver im Netzwerk? (Single Source of Truth)

Würden zwei Clients direkt miteinander sprechen, müsste jeder Client lokal mitzählen, wie viele Hölzchen noch übrig sind. Das führt zu schweren Problemen:

  • Inkonsistenzen: Wenn Nachrichten verzögert ankommen, könnten beide Clients unterschiedliche Bestände anzeigen.
  • Cheating: Ein manipulierter Client könnte einfach behaupten: „Ich nehme 10 Hölzchen und habe gewonnen“.
  • Zustandsverlust: Wer entscheidet neutral, wer gerade am Zug ist?

Lösung: Der NimmServer verwaltet den alleinigen Spielzustand (Attribute anzahlObjekte, aktiverSpieler). Die Clients sind reine Ein- und Ausgabestationen.

2

Das Anwendungsprotokoll: Spezifikation vor Code

In Rechnernetzen gilt der Leitsatz: Erst das Protokoll festlegen, dann programmieren! Ein Netzwerk-Client und ein Server können sich nur verständigen, wenn die Syntax (Befehle) und die Semantik (Bedeutung) millimetergenau geklärt sind.

Übersicht der Protokollbefehle (Text-basiertes Protokoll)

Befehl / Format Absender Empfänger Bedeutung / Auswirkung
START <nr> Server Client Eröffnet das Spiel. Teilt dem Client seine Spielernummer (1 oder 2) mit.
DRAN <n> Server Aktiver Client Aufforderung zum Zug. Übermittelt den aktuellen Restbestand $n$.
WARTEN <n> Server Passiver Client Informiert den wartenden Spieler über den aktuellen Restbestand $n$.
NIMM <k> Client Server Der aktive Spieler zieht $k$ Objekte ($k \in \{1, 2, 3\}$).
GEWONNEN Server Sieger Der Gegenspieler hat das letzte Objekt genommen. Du hast gewonnen!
VERLOREN Server Verlierer Du hast das letzte Objekt genommen und somit verloren.
FEHLER <grund> Server Client Ungültiger Zug (z. B. falscher Spieler, $k > 3$ oder $k > n$).
INFO <text> Server Client Allgemeine Statusmeldungen (z. B. beim Warten auf Spieler 2).

Der fertige NimmClient: Wie funktioniert er?

Um dich ganz auf die anspruchsvolle Netzwerk- und Spiellogik des Servers zu konzentrieren, ist die Klasse NimmClient bereits vollständig für dich vorbereitet.

  • Verbindung: Erzeugt man ein Objekt via new NimmClient(), verbindet er sich automatisch mit 127.0.0.1:50000.
  • Zug ausführen: Die Methode ziehe(int pAnzahl) validiert lokal, ob $1 \le pAnzahl \le 3$ gilt, und sendet anschließend send("NIMM " + pAnzahl).
  • Antworten darstellen: Die geerbte Methode processMessage(String pMessage) zerlegt die Server-Befehle und gibt verständliche Konsolentexte aus.

Der NimmServer: Deine Programmieraufgabe

Die Klasse NimmServer extends Server besitzt bereits das Attribut-Gerüst und praktische Hilfsmethoden (z. B. sendeAnSpieler, sendeAnBeide, zuruecksetzen). Deine Aufgabe ist es nun, die geerbten Methoden Schritt für Schritt auszufüllen.

M1

Meilenstein 1: Spielerverwaltung & Verbindungsannahme

Methode: public void processNewConnection(String pClientIP, int pClientPort)

Sobald ein Client anklopft, ruft der Server-Hintergrundthread diese Methode auf. Der Server muss sich merken, wer Spieler 1 und wer Spieler 2 ist.

Aufgabenstellung für Meilenstein 1:
  1. Prüfe, ob der Platz für Spieler 1 frei ist (spieler1IP == null). Falls ja: IP und Port abspeichern und dem Client eine Begrüßung via send(...) schicken.
  2. Falls Spieler 1 schon da ist, prüfe, ob Spieler 2 frei ist. Falls ja: Abspeichern und starteSpiel() aufrufen!
  3. Falls bereits 2 Spieler verbunden sind und ein dritter Client anklopft: Sende eine Fehlermeldung und trenne ihn mit closeConnection(pClientIP, pClientPort).
Musterlösung Meilenstein 1: 
@Override
public void processNewConnection(String pClientIP, int pClientPort) {
    if (spieler1IP == null) {
        spieler1IP = pClientIP;
        spieler1Port = pClientPort;
        send(pClientIP, pClientPort, "INFO Du bist Spieler 1. Warte auf Gegenspieler...");
    } else if (spieler2IP == null) {
        spieler2IP = pClientIP;
        spieler2Port = pClientPort;
        send(pClientIP, pClientPort, "INFO Du bist Spieler 2. Spiel startet sofort!");
        starteSpiel();
    } else {
        send(pClientIP, pClientPort, "FEHLER Das Spiel ist bereits voll (2/2 Spieler).");
        closeConnection(pClientIP, pClientPort);
    }
}
M2

Meilenstein 2: Der Protokoll-Parser & Zugrecht

Methode: public void processMessage(String pClientIP, int pClientPort, String pMessage)

Diese Methode empfängt den vom Client gesendeten Text (z. B. "NIMM 2"). Vor jeder Berechnung muss streng geprüft werden, ob der Absender überhaupt spielberechtigt ist!

Aufgabenstellung für Meilenstein 2:
  1. Prüfe, ob das Spiel überhaupt aktiv ist (!spielAktiv).
  2. Ermittle anhand der IP und des Ports, ob die Nachricht von Spieler 1 oder Spieler 2 stammt (Nutze istSpieler1(...) bzw. istSpieler2(...)).
  3. Prüfe, ob dieser Spieler an der Reihe ist (absenderNummer == aktiverSpieler). Wenn nicht: Sende "FEHLER Du bist nicht an der Reihe!".
  4. Prüfe, ob der Text mit "NIMM " beginnt. Extrahiere die Zahl mit Integer.parseInt(...) und rufe fuehreZugAus(...) auf.
Musterlösung Meilenstein 2: 
@Override
public void processMessage(String pClientIP, int pClientPort, String pMessage) {
    if (!spielAktiv) {
        send(pClientIP, pClientPort, "FEHLER Kein Spiel aktiv.");
        return;
    }

    int absender = 0;
    if (istSpieler1(pClientIP, pClientPort)) absender = 1;
    else if (istSpieler2(pClientIP, pClientPort)) absender = 2;

    if (absender != aktiverSpieler) {
        send(pClientIP, pClientPort, "FEHLER Du bist nicht an der Reihe! Bitte warten.");
        return;
    }

    if (pMessage.startsWith("NIMM ")) {
        try {
            int anzahl = Integer.parseInt(pMessage.substring(5).trim());
            fuehreZugAus(absender, anzahl);
        } catch (NumberFormatException e) {
            send(pClientIP, pClientPort, "FEHLER Ungueltige Zahl nach NIMM.");
        }
    } else {
        send(pClientIP, pClientPort, "FEHLER Unbekannter Befehl.");
    }
}
M3

Meilenstein 3: Spielstand aktualisieren & Rollenwechsel

Methode: public void fuehreZugAus(int pSpielerNr, int pAnzahl)

Aufgabenstellung für Meilenstein 3:
  1. Prüfe, ob $pAnzahl$ zwischen $1$ und $3$ liegt. Falls nicht: Fehlermeldung senden und den Spieler erneut auffordern.
  2. Prüfe, ob $pAnzahl \le anzahlObjekte$. Man darf nicht mehr Hölzchen nehmen, als auf dem Tisch liegen!
  3. Ziehe $pAnzahl$ von anzahlObjekte ab.
  4. Wechsle das Zugrecht: Wenn aktiverSpieler == 1 war, ist jetzt Spieler 2 dran (und umgekehrt).
  5. Sende an den neuen aktiven Spieler "DRAN " + anzahlObjekte und an den anderen "WARTEN " + anzahlObjekte.
Musterlösung Meilenstein 3 (Zwischenstand ohne Spielende): 
public void fuehreZugAus(int pSpielerNr, int pAnzahl) {
    if (pAnzahl < 1 || pAnzahl > 3) {
        sendeAnSpieler(pSpielerNr, "FEHLER Nur 1 bis 3 Objekte erlaubt!");
        sendeAnSpieler(pSpielerNr, "DRAN " + anzahlObjekte);
        return;
    }
    if (pAnzahl > anzahlObjekte) {
        sendeAnSpieler(pSpielerNr, "FEHLER Es sind nur noch " + anzahlObjekte + " Objekte da!");
        sendeAnSpieler(pSpielerNr, "DRAN " + anzahlObjekte);
        return;
    }

    anzahlObjekte -= pAnzahl;

    // Rollenwechsel
    aktiverSpieler = (aktiverSpieler == 1) ? 2 : 1;
    int wartender = (aktiverSpieler == 1) ? 2 : 1;

    sendeAnSpieler(aktiverSpieler, "DRAN " + anzahlObjekte);
    sendeAnSpieler(wartender, "WARTEN " + anzahlObjekte);
}
M4

Meilenstein 4: Misère-Spielende & Verbindungsabbruch

Nun wird die Misère-Regel in fuehreZugAus integriert und das vorzeitige Verlassen eines Spielers in processClosingConnection abgefangen.

Aufgabenstellung für Meilenstein 4:
  1. Spielende auswerten: Wenn nach dem Abzug anzahlObjekte <= 0 gilt, hat der ziehende Spieler das letzte Objekt genommen:
    ➔ Sende an den Ziehenden "VERLOREN".
    ➔ Sende an den Gegenspieler "GEWONNEN".
    ➔ Setze spielAktiv = false;.
  2. Verbindungsabbruch: Verlässt ein Spieler während des Spiels den Server (processClosingConnection), muss der verbliebene Spieler eine Abbruchmeldung erhalten und der Server zurückgesetzt werden.
Musterlösung Meilenstein 4: 
// In fuehreZugAus(...) direkt nach anzahlObjekte -= pAnzahl:
if (anzahlObjekte <= 0) {
    int sieger = (pSpielerNr == 1) ? 2 : 1;
    sendeAnSpieler(pSpielerNr, "VERLOREN");
    sendeAnSpieler(sieger, "GEWONNEN");
    spielAktiv = false;
} else {
    aktiverSpieler = (aktiverSpieler == 1) ? 2 : 1;
    sendeAnSpieler(aktiverSpieler, "DRAN " + anzahlObjekte);
    sendeAnSpieler((aktiverSpieler == 1 ? 2 : 1), "WARTEN " + anzahlObjekte);
}

// In processClosingConnection(...):
@Override
public void processClosingConnection(String pClientIP, int pClientPort) {
    if (istSpieler1(pClientIP, pClientPort)) {
        if (spielAktiv && spieler2IP != null) {
            sendeAnSpieler(2, "INFO Spieler 1 hat das Spiel verlassen.");
        }
        zuruecksetzen();
    } else if (istSpieler2(pClientIP, pClientPort)) {
        if (spielAktiv && spieler1IP != null) {
            sendeAnSpieler(1, "INFO Spieler 2 hat das Spiel verlassen.");
        }
        zuruecksetzen();
    }
}

Gestufte Hilfekarten

Wähle genau die Hilfestufe, die du gerade benötigst. Versuche zunächst immer mit Stufe 1 weiterzukommen, bevor du Code nachschlägst.

Hilfekarte A: Wie unterscheidet der Server Spieler 1 und Spieler 2?

Stufe 1 (Logik): Jedes Netzwerkpaket bringt pClientIP und pClientPort mit. Vergleiche diese beiden Werte einfach mit den Attributen spieler1IP und spieler1Port.
Stufe 2 (Code-Gerüst): 
if (pClientIP.equals(spieler1IP) && pClientPort == spieler1Port) {
    // Absender ist Spieler 1!
}

Hilfekarte B: Wie zerlege ich "NIMM 2" in Java?

Stufe 1 (Logik): Das Wort "NIMM " hat 5 Zeichen (Index 0 bis 4). Alles ab Index 5 ist die gewünschte Zahl.
Stufe 2 (Code-Gerüst): 
String zifferText = pMessage.substring(5).trim();
int anzahl = Integer.parseInt(zifferText);

Hilfekarte C: Wie wechsle ich elegant zwischen Spieler 1 und 2?

Stufe 1 (Logik): Wenn aktiverSpieler == 1 ist, wird er zu 2. Ansonsten wird er wieder zu 1.
Stufe 2 (Code-Gerüst): 
// Klassisch mit if-else:
if (aktiverSpieler == 1) {
    aktiverSpieler = 2;
} else {
    aktiverSpieler = 1;
}

// Oder kurz als Einzeiler:
aktiverSpieler = (aktiverSpieler == 1) ? 2 : 1;
