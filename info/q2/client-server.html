Der Schritt ins Netzwerk: Warum reicht normaler Java-Code nicht mehr?

Bisher lebten alle unsere Objekte im selben Arbeitsspeicher (RAM) eines einzigen Computers. Wenn unser Krieger einen Magier angegriffen hat, genügte ein direkter Methodenaufruf: 

meinKrieger.angreifen(meinMagier); // Funktioniert nur im selben Speicher!

Das Problem zweier getrennter Computer:

Sitzt Spieler A an PC 01 und Spieler B an PC 12, existiert kein gemeinsamer Arbeitsspeicher. Ein Methodenaufruf kann nicht einfach über ein LAN-Kabel fliegen.

Das Rollenmodell: Client und Server

Damit zwei Computer im Netzwerk miteinander sprechen können, teilen wir ihnen feste Rollen zu:

Rolle Verhalten Alltags-Analogie
Server (Dienstanbieter) Wartet passiv auf einem festgelegten Port, nimmt Verbindungen an und antwortet auf Anfragen. Läuft dauerhaft. Ein Taxistand oder ein Restaurant: Das Restaurant hat feste Öffnungszeiten und wartet, bis Gäste eintreffen.
Client (Dienstnutzer) Wird aktiv tätig, kontaktiert den Server unter dessen IP-Adresse und Port und sendet Anfragen. Der Gast, der das Restaurant betritt und eine Bestellung aufgibt.
Merke: Das Schiedsrichter-Prinzip
Im Mehrspieler-Spiel ist der Server der unparteiische Schiedsrichter (Single Source of Truth). Er verwaltet die echten Lebenspunkte und Schadenswerte. Clients sind lediglich „Bildschirm und Tastatur“: Sie schicken Befehle ab und zeigen an, was der Server entschieden hat. Das verhindert Schummeln (Cheating)!

Das Konzept: Abstrakte Klassen und abstrakte Methoden

Um die Netzwerkklassen von Java zu verstehen, müssen wir eine fundamentale OOP-Erweiterung unserer Vererbung kennenlernen: das Schlüsselwort abstract.

Der Bauplan mit Lücken (Die Vertragsklausel)

In unserer Rollenspiel-Hierarchie gab es die Oberklasse Spielfigur. Technisch konnte man new Spielfigur("Max", 100, 10) erzeugen. Aber im echten Spiel macht eine „gesichtslose Standardfigur“ ohne Spezialisierung keinen Sinn!

Eine abstrakte Klasse ist ein unvollständiger Bauplan. Sie dient ausschließlich als gemeinsame Basis für Unterklassen. Java verbietet es, von einer abstrakten Klasse direkt mit new Objekte zu erzeugen!

Konzept Java-Syntax Bedeutung für Entwickler
Abstrakte Klasse public abstract class Client { ... } Kann nicht mit new Client(...) instanziiert werden. Man muss eine Unterklasse schreiben (z. B. class EchoClient extends Client).
Abstrakte Methode public abstract void processMessage(String pMsg); Besitzt keinen Methodenrumpf (keine geschweiften Klammern { }, sondern endet mit ;). Sie ist ein Vertrag: Jede konkrete Unterklasse muss diese Methode mit @Override implementieren!
Merke: Der abstrakte Vertrag
Eine abstrakte Methode sagt: „Ich als Oberklasse lege fest, DASS jede Unterklasse diese Fähigkeit besitzen muss – aber WIE sie genau funktioniert, entscheidet die Unterklasse!“ Vergisst eine Unterklasse das Überschreiben einer abstrakten Methode, verweigert der Java-Compiler das Kompilieren.

Das Blackbox-Prinzip: Warum die Abiturklassen abstrakt sind

Wenn zwei Computer über TCP/IP Daten austauschen, verlangt Java normalerweise dutzende Zeilen anspruchsvollen Code: Ports öffnen, Sockets verwalten, Datenströme puffern und vor allem parallele Hintergrund-Prozesse (Multithreading), damit das Programm beim Warten auf Nachrichten nicht einfriert.

Der „Deckel-drauf“-Effekt

Die offiziellen Abiturklassen Client und Server packen diese gesamte Netzwerk-Maschinerie in ein fertiges Gehäuse und schrauben den Deckel fest zu (Blackbox). Als Schülerin oder Schüler müsst ihr die inneren Details nicht kennen.

Die zwei Anschlüsse an der Blackbox:

  1. Der Knopf zum Senden (Aktiv): Mit send("Hallo") werft ihr einen Text in die Box. Die Box sorgt geräuschlos dafür, dass die Bits durch die Netzwerkkarte zum Partner wandern.
  2. Die Klingel bei Post (Passiv / Callback): Ihr müsst nicht ständig in einer Schleife prüfen, ob eine Nachricht da ist. Sobald Post eintrifft, klingelt die Blackbox an eurer Tür und ruft automatisch eure Methode processMessage(...) auf!

Warum ist Client nun abstrakt? Weil die Blackbox alles über Kabel, Sockets und Ports weiß, aber keine Gedanken lesen kann: Sie weiß, dass Text eingetroffen ist – aber sie kann nicht wissen, ob ihr einen Chat, eine Notaufnahme oder ein rundenbasiertes Rollenspiel baut. Daher verlangt sie von euch die Implementierung von processMessage.

Die Abiturklassen im Detail: Schnittstellen-Steckbrief

1. Die Klasse Client (Client-Sicht)

Methode Art Wirkung
Client(String pIP, int pPort) Konstruktor Verbindet sich sofort mit dem angegebenen Server.
boolean isConnected() Fertig geerbt Gibt true zurück, falls die Verbindung aktiv ist.
void send(String pMessage) Fertig geerbt Sendet eine Textzeile an den Server.
void close() Fertig geerbt Trennt die Verbindung zum Server ordnungsgemäß.
abstract void processMessage(String pMessage) Muss überschrieben werden Wird vom Hintergrund-Thread aufgerufen, sobald eine Antwort des Servers eintrifft.

2. Die Klasse Server (Server-Sicht)

Methode Art Wirkung
Server(int pPort) Konstruktor Öffnet den Port und wartet auf eingehende Client-Verbindungen.
void send(String ip, int port, String msg) Fertig geerbt Sendet Text an genau einen bestimmten Client.
void sendToAll(String msg) Fertig geerbt Sendet Text an alle aktuell verbundenen Clients (Broadcast).
void closeConnection(String ip, int port) Fertig geerbt Trennt die Verbindung zu einem bestimmten Client.
abstract void processNewConnection(String ip, int port) Hook 1 Wird aufgerufen, wenn sich ein neuer Client anmeldet.
abstract void processMessage(String ip, int port, String msg) Hook 2 Wird aufgerufen, wenn ein Client Text geschickt hat.
abstract void processClosingConnection(String ip, int port) Hook 3 Wird aufgerufen, wenn ein Client die Verbindung trennt.

Parameterfluss & Methodenaufrufe mit konkreten Werten

Damit die abstrakten Methoden greifbar werden, betrachten wir ein reales Klassenzimmer-Szenario mit echten Zahlen und Zeichenketten, die durch den Java-Code wandern:

Das Ausgangsszenario:

  • Lehrer-PC (Server): IP-Adresse 192.168.1.100, geöffneter Port 50000.
  • Schüler Kevin (Client): PC 12 mit IP 192.168.1.42. Sein Betriebssystem teilt ihm für die Verbindung temporär den freien Port 54321 zu.
Ablauf 1: Verbindungsaufbau → Hook 1 (processNewConnection)

1. Was Kevin im Code aufruft:

EchoClient kevin = new EchoClient("192.168.1.100", 50000);

2. Was die Server-Blackbox automatisch aufruft:

processNewConnection("192.168.1.42", 54321);

3. Was im Servercode passiert und wie Parameter weitergereicht werden:

@Override
public void processNewConnection(String pClientIP, int pClientPort) {
    // pClientIP   erhaelt den Wert "192.168.1.42"
    // pClientPort erhaelt den Wert 54321

    System.out.println("Neuer Client da: " + pClientIP + " an Port " + pClientPort);

    // PARAMETER-WEITERREICHUNG:
    // Wir reichen pClientIP und pClientPort direkt an send(...) durch!
    send(pClientIP, pClientPort, "WILLKOMMEN: Du bist verbunden!");
}
Ablauf 2: Kevin sendet Text → Hook 2 (processMessage)

1. Kevin schickt eine Nachricht ab:

kevin.send("Hallo Herr Lehrer!");

2. Das TCP-Paket wandert durchs Netzwerkkabel. Auf dem Server ruft die Blackbox auf:

processMessage("192.168.1.42", 54321, "Hallo Herr Lehrer!");

3. Die Weiterreichung der Parameter im Server-Code:

@Override
public void processMessage(String pClientIP, int pClientPort, String pMessage) {
    // Werte der Parameter:
    // pClientIP   = "192.168.1.42"
    // pClientPort = 54321
    // pMessage    = "Hallo Herr Lehrer!"

    // 1. Text verarbeiten & Antwort vorbereiten:
    String antwort = "Echo: " + pMessage; // "Echo: Hallo Herr Lehrer!"

    // 2. ENTSCHEIDENDE ZEILE: Wir uebergeben pClientIP und pClientPort an send(...),
    //    damit genau Kevin die Antwort erhaelt und nicht sein Sitznachbar!
    send(pClientIP, pClientPort, antwort);
}
Ablauf 3: Die Server-Antwort erreicht Kevin

Was die Client-Blackbox auf Kevins Rechner aufruft:

processMessage("Echo: Hallo Herr Lehrer!");

Kevins Client-Code führt aus:

@Override
public void processMessage(String pMessage) {
    // pMessage hat den Wert "Echo: Hallo Herr Lehrer!"
    System.out.println("Vom Server erhalten: " + pMessage);
}

Der Aha-Effekt: Warum hat der Client weniger Parameter?

Klasse Methoden-Signatur Warum diese Parameter?
Server processMessage(String ip, int port, String msg) 3 Parameter: Der Server bedient viele Clients gleichzeitig. Er muss wissen: Wer hat geschrieben (ip, port) und was steht drin (msg)?
Client processMessage(String msg) Nur 1 Parameter: Der Client ist nur mit einem einzigen Server verbunden. Er weiß ohnehin, wer absendet – er benötigt nur den Textinhalt (msg)!
Ablauf 4: Kevin trennt die Verbindung → Hook 3 (processClosingConnection)

Kevin ruft auf: kevin.close();

Die Server-Blackbox meldet den Abgang:

processClosingConnection("192.168.1.42", 54321);
@Override
public void processClosingConnection(String pClientIP, int pClientPort) {
    System.out.println("Teilnehmer hat das Netzwerk verlassen: " + pClientIP);
}

Praxis-Leitfaden: Das 2-Stufen-Prinzip in BlueJ

Öffne das heruntergeladene Projekt BlueJ_Client_Server. Wir gehen in zwei klaren Stufen vor:

Stufe 1: Autarker Test am eigenen Computer (Localhost)

  1. Rechtsklick auf EchoServer → new EchoServer() aufrufen. Der Server lauscht auf Port 50000.
  2. Rechtsklick auf EchoClient → new EchoClient() aufrufen. Er verbindet sich mit 127.0.0.1.
  3. Rechtsklick auf das rote Client-Objekt unten links → Methode sendeNachricht("Dein Text") ausführen.
  4. Öffne das Terminal-Fenster in BlueJ: Du siehst das Echo des Servers!

Stufe 2: Partnerarbeit im Schul-Netzwerk (Rechnerübergreifend)

  1. Dein Sitznachbar startet den EchoServer.
  2. Finde die IP-Adresse deines Nachbarn heraus (im Windows-Terminal: Befehl ipconfig eingeben, dort die IPv4-Adresse ablesen, z. B. 192.168.1.45).
  3. Erzeuge auf deinem Rechner einen EchoClient mit den Parametern:
    new EchoClient("192.168.1.45", 50000)
  4. Sende eine Nachricht ab – sie wandert nun physisch durch das Netzwerkkabel deines Nachbarn!

Praktische Übungsaufgaben zur Methoden-Vertiefung

Bearbeite die folgenden Aufgaben schrittweise in deiner BlueJ-Klasse EchoServer, um die Methoden und Parameter souverän zu beherrschen.

Aufgabe 1 Der Parameter-Detektiv (Trockenübung)
Verständnis

Schülerin Mia sitzt an PC 05 mit der IP 192.168.1.15 (ihr Client-Port ist 49152). Sie schickt die Nachricht "Wie spät ist es?" an den EchoServer.

Deine Aufgabe:
1. Welche Methode auf dem Server wird von der Blackbox aufgerufen?
2. Welche exakten Werte haben die drei Parameter?
3. Wie lautet der Java-Befehl im Server, um Mia die Antwort "12:00 Uhr" zurückzusenden?

Musterlösung anzeigen
1. Aufgerufene Methode: processMessage(String pClientIP, int pClientPort, String pMessage)
2. Konkrete Parameterwerte:
  • pClientIP = "192.168.1.15"
  • pClientPort = 49152
  • pMessage = "Wie spät ist es?"
3. Rücksende-Befehl: 
send(pClientIP, pClientPort, "12:00 Uhr");
(oder alternativ mit den Literalen: send("192.168.1.15", 49152, "12:00 Uhr");)
Aufgabe 2 Der Großbuchstaben-Server (Caps-Bot)
Code-Modifikation

Bisher antwortet der EchoServer mit "Echo: " + pMessage.

Deine Aufgabe: Ändere die Methode processMessage im EchoServer so ab, dass jeder eingehende Text komplett in GROSSBUCHSTABEN umgewandelt zurückgesendet wird.
Tipp: Nutze die Java-Standardmethode pMessage.toUpperCase().

Musterlösung anzeigen

In EchoServer.java wird processMessage angepasst:

@Override
public void processMessage(String pClientIP, int pClientPort, String pMessage) {
    System.out.println("[SERVER] Empfangen von " + pClientIP + ": " + pMessage);

    // Text in Grossbuchstaben umwandeln:
    String antwort = pMessage.toUpperCase();

    // Zurueck an genau diesen Client schicken:
    send(pClientIP, pClientPort, antwort);
}
Aufgabe 3 Der Raum-Chat: Broadcast mit sendToAll
Abitur-Methode

In einem Chat soll eine Nachricht nicht nur an den Absender zurückgehen, sondern an alle Schülerinnen und Schüler im Raum weitergeleitet werden.

Deine Aufgabe: Ersetze in processMessage den Aufruf send(...) durch die geerbte Methode sendToAll(...). Die Nachricht soll anzeigen, von welcher IP sie stammt:
Format: "[" + pClientIP + "]: " + pMessage

Musterlösung anzeigen 
@Override
public void processMessage(String pClientIP, int pClientPort, String pMessage) {
    // Chat-Nachricht formatieren:
    String chatNachricht = "[" + pClientIP + "]: " + pMessage;

    // An ALLE verbundenen Clients ausstrahlen:
    sendToAll(chatNachricht);
}

Hinweis: Bei sendToAll entfallen IP und Port als Parameter, weil die Blackbox die Nachricht automatisch an jeden angemeldeten Client schickt!

Aufgabe 4 Der Besucher-Zähler (Zustand im Server)
OOP & Attribute

Der Server soll sich merken, wie viele Clients sich seit dem Start insgesamt verbunden haben.

Deine Aufgabe:
1. Lege im EchoServer ein Attribut private int besucherZahl = 0; an.
2. Erhöhe diesen Zähler in processNewConnection jedes Mal um 1.
3. Sende dem neuen Client eine persönliche Begrüßung mit seiner Nummer:
„Willkommen! Du bist Besucher Nummer [X]!“

Musterlösung anzeigen

1. Attribut oben in der Klasse EchoServer deklarieren:

public class EchoServer extends Server {
    private int besucherZahl = 0;
    // ...

2. In processNewConnection hochzählen und versenden:

@Override
public void processNewConnection(String pClientIP, int pClientPort) {
    this.besucherZahl++; // Zaehler um 1 erhoehen
    
    System.out.println("Besucher #" + this.besucherZahl + " verbunden von " + pClientIP);

    String begruessung = "Willkommen! Du bist Besucher Nummer " + this.besucherZahl + "!";
    send(pClientIP, pClientPort, begruessung);
}
Aufgabe 5 Der Ping-Pong-Bot (Erste Fallunterscheidung)
Protokoll-Basis

Nun soll der Server nicht mehr blind jeden Text spiegeln, sondern auf bestimmte Schlüsselwörter reagieren.

Deine Aufgabe: Baue in processMessage eine Fallunterscheidung mit if / else ein:
• Wenn pMessage gleich "PING" ist → Antworte mit "PONG".
• Wenn pMessage gleich "INFO" ist → Antworte mit "Ich bin der Q2-Lernserver Version 1.0".
• Bei allem anderen → Antworte mit "UNBEKANNTER BEFEHL: " + pMessage.
Achtung: Strings vergleicht man in Java immer mit .equals(...), niemals mit ==!

Musterlösung anzeigen 
@Override
public void processMessage(String pClientIP, int pClientPort, String pMessage) {
    if (pMessage.equalsIgnoreCase("PING")) {
        send(pClientIP, pClientPort, "PONG");
    } else if (pMessage.equalsIgnoreCase("INFO")) {
        send(pClientIP, pClientPort, "Ich bin der Q2-Lernserver Version 1.0");
    } else {
        send(pClientIP, pClientPort, "UNBEKANNTER BEFEHL: " + pMessage);
    }
}

Erkenntnis: Das ist bereits der Kern jedes Netzwerkprotokolls! Genau so steuern wir später im Rollenspiel Befehle wie ANGRIFF oder HEILEN.

Ausblick: Vom Echo zum Rollenspiel-Duell (Das Protokoll)

Unser EchoServer schickt bisher nur einfachen Text zurück. Für ein echtes Online-Duell zwischen Krieger und Magier müssen sich Client und Server über eine feste Sprache verständigen: ein Anwendungsprotokoll.

Das Trennzeichen-Prinzip mit split(":")

Wir trennen Befehle und Parameter durch Doppelpunkte. In Java lässt sich das mit einer einzigen Zeile zerlegen: 

// Eingehende Nachricht: "ANGRIFF:KRIEGER:SCHWERT"
String[] teile = pMessage.split(":");
String befehl = teile[0];  // "ANGRIFF"
String klasse = teile[1];  // "KRIEGER"
String waffe  = teile[2];  // "SCHWERT"

Im nächsten Schritt setzen wir unsere Rollenspielfiguren auf den Server und steuern ihre Angriffe genau über solche Protokoll-Befehle!

Verständnisfragen zur Selbstkontrolle

Frage 1: Warum kann man nicht einfach new Client("127.0.0.1", 50000) aufrufen?
Erklärung: Die Klasse Client ist als abstract deklariert. Java verbietet es prinzipiell, von abstrakten Klassen direkt Instanzen mit new zu erzeugen. Der Grund: Client enthält die unvollständige Methode processMessage, die erst von einer konkreten Unterklasse (wie EchoClient) mit Leben gefüllt werden muss.
Frage 2: Was ist der Unterschied zwischen einer IP-Adresse und einer Portnummer?
Erklärung: Die IP-Adresse adressiert das physische Gerät im Netzwerk (wie die Hausanschrift eines Mehrfamilienhauses). Die Portnummer (0 bis 65535) adressiert das konkrete Programm bzw. den Dienst auf diesem Rechner (wie die Wohnungsnummer oder das Namensschild an der Klingel). Ein Server kann mehrere Ports gleichzeitig für unterschiedliche Programme (Web, Echo, Spiel) geöffnet haben.
Frage 3: Warum bezeichnet man processMessage als Callback- bzw. Hook-Methode?
Erklärung: Weil der Programmierer diese Methode nicht selbst aktiv im Code aufruft. Stattdessen ruft der im Hintergrund laufende Thread der Blackbox (das Framework) automatisch unsere Methode auf, sobald neue Bytes über das Netzwerk empfangen wurden. Das Framework "hakt sich" bei uns ein (Hook).
Frage 4: Was bedeutet die IP-Adresse 127.0.0.1 bzw. der Name localhost?
Erklärung: 127.0.0.1 ist die standardisierte Loopback-Adresse eines Computers. Netzwerkpakete, die an diese Adresse geschickt werden, verlassen das Gerät nicht, sondern werden vom Betriebssystem direkt intern an den Zielport auf demselben Rechner weitergeleitet. Ideal zum fehlerfreien Testen ohne äußeres Netzwerk!
