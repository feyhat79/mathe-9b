1

Das mentale Modell: Bauplan versus Einzelstück

In der realen Welt backt man Kekse nicht aus dem Nichts – man nutzt eine Ausstechform. Aus einer einzigen Form entstehen Dutzende Kekse, die sich in Verzierung oder Knusprigkeit unterscheiden können. Dieses Prinzip ist das Herzstück der modernen Informatik:

Klasse Der Bauplan / Typ

Die Klasse definiert allgemein, welche Eigenschaften (Attribute) und Fähigkeiten (Methoden) alle Objekte dieser Art besitzen werden. Sie ist die Idee im Quelltext.

Objekt Das konkrete Einzelstück

Das Objekt ist die konkrete Instanz im Speicher. Es besitzt eigene Attributwerte (Zustand), reagiert auf Methodenaufrufe und hat eine eindeutige Identität.

Der Zustand eines Objekts wird durch die Gesamtheit seiner aktuellen Attributwerte bestimmt (z. B. Position $x=120$, $y=80$, Farbe = „rot“, Größe = 60). Methoden verändern diesen Zustand.

Das BlueJ-Signal: Warum ist der Kasten schraffiert?

Wenn du in BlueJ eine Klasse neu anlegst oder ihren Quelltext bearbeitest, ist der Kasten grau gestreift (schraffiert). Bedeutung: Die Datei .java wurde geändert, aber es existiert noch keine aktuelle .class-Datei! Erst wenn du auf „Übersetzen“ (Compile) klickst, erzeugt der Compiler den Bytecode und die Schraffur verschwindet.

Syntaxfehler vs. Logischer Fehler:

• Syntaxfehler: Verstoß gegen die Rechtschreibung von Java (z. B. Semikolon vergessen). Der Compiler stoppt sofort.

• Logischer Fehler: Der Code übersetzt perfekt, aber das Programm tut nicht das Gewünschte (z. B. Minus- statt Pluszeichen bei der Bewegung).

Der Begriffs-TÜV: Klasse, Konstruktor und Objekt

Bevor wir komplexe Programme schreiben, klären wir den wichtigsten Unterschied:

1. Bauplan Klasse

Quelltext im Editor (Kreis.java). Definiert Attribute und Methoden abstrakt.

2. Geburtsstunde Konstruktor

Die Initialisierungsmethode (public Kreis()). Läuft genau einmal beim Erschaffen und setzt Startwerte.

3. Einzelstück Objekt

Die konkrete Instanz im Speicher (rote Box). Hat eigenen Zustand und eigene Identität.

Vom Mausklick zum Quellcode: Der new-Operator & Punktnotation

Das Klick-Dilemma

Ein Haus auf der Werkbank benötigt über 25 manuelle Klicks. Beim Neustart von BlueJ ist alles weg. Die Lösung: Wir schreiben den Ablauf als Programmcode in eine neue Klasse!

1. Objekterzeugung im Quelltext:

Quadrat wand = new Quadrat();

Typ + Variablenname $\rightarrow$ new reserviert Speicher $\rightarrow$ Quadrat() ruft Konstruktor auf.

2. Die Punktnotation:

wand . groesseAendern( 120 );

Der Punkt (.) sendet den Befehl direkt an das referenzierte Objekt.

3

Programmier-Labor: Die Klasse Bild („Hat-ein“-Beziehung)

Erstelle in BlueJ eine neue Klasse Bild. Das Bild steuert als übergeordnetes Objekt Wand, Dach, Fenster und Sonne: 

public class Bild {
    // Attribute: Das Bild besitzt Figuren (Referenzen)
    private Quadrat wand;
    private Dreieck dach;
    private Quadrat fenster;
    private Kreis   sonne;

    // Konstruktor: Erschafft alle Einzelteile im Speicher
    public Bild() {
        wand = new Quadrat();
        dach = new Dreieck();
        fenster = new Quadrat();
        sonne = new Kreis();
    }

    // Methode zeichne: Baut die Szene auf Knopfdruck auf
    public void zeichne() {
        wand.groesseAendern(120);
        wand.farbeAendern("rot");
        wand.horizontalBewegen(-50);
        wand.vertikalBewegen(80);
        wand.sichtbarMachen();

        fenster.farbeAendern("schwarz");
        fenster.groesseAendern(35);
        fenster.horizontalBewegen(-15);
        fenster.vertikalBewegen(120);
        fenster.sichtbarMachen();

        dach.farbeAendern("gruen");
        dach.groesseAendern(60, 150);
        dach.horizontalBewegen(20);
        dach.vertikalBewegen(45);
        dach.sichtbarMachen();

        sonne.farbeAendern("gelb");
        sonne.groesseAendern(65);
        sonne.horizontalBewegen(125);
        sonne.vertikalBewegen(-30);
        sonne.sichtbarMachen();
    }
}

Zusatzaufgabe: sonnenuntergang()

Die Sonne wandert langsam nach unten (langsamVertikalBewegen(250)) und färbt sich blau.

Lösung anzeigen: 
public void sonnenuntergang() {
    sonne.langsamVertikalBewegen(250);
    sonne.farbeAendern("blau");
}

Zusatzaufgabe: nachtModus()

Sonne wird unsichtbar, Wand färbt sich dunkelblau und das Fenster wird gelb (Licht im Haus an!).

Lösung anzeigen: 
public void nachtModus() {
    sonne.unsichtbarMachen();
    wand.farbeAendern("blau");
    fenster.farbeAendern("gelb");
}

Merkhefteintrag: Die Kernkonzepte der OOP

MERKE
Zusammenfassung: Objektorientierte Modellierung

1. Klasse vs. Konstruktor vs. Objekt:
• Klasse: Der Bauplan / Typ im Quelltext (.java).
• Konstruktor: Die spezielle Initialisierungsmethode in der Klasse. Heißt exakt wie die Klasse und läuft genau einmal bei der Erschaffung.
• Objekt: Die konkrete Instanz im Arbeitsspeicher mit eigenem Zustand.

2. Objekterzeugung mit new:
Klassenname objektName = new Klassenname();
Der Operator new reserviert Arbeitsspeicher und führt den Konstruktor aus.

3. Die Punktnotation:
objektName.methodenName(parameterWert);
Sendet eine Botschaft an ein existierendes Objekt.

4. Komposition („Hat-ein“-Beziehung):
Ein komplexes Objekt (z. B. Bild) besitzt Referenzen auf andere Objekte als Attribute und koordiniert deren Zusammenspiel.

2

Detektiv-Check: Typische Fehlerquellen verstehen

Frage 1: Was passiert, wenn man im Konstruktor Bild() die Zeile sonne = new Kreis(); vergisst?
Das Programm stürzt beim Aufruf von sonne.sichtbarMachen() mit einer NullPointerException ab! Die Variable sonne zeigt ohne new auf den Leerraum (null).
Frage 2: Warum stehen die Attribute ganz oben in der Klasse Bild und nicht in der Methode zeichne()?
Weil sie dauerhafte Eigenschaften des Bild-Objekts sein müssen! Variablen innerhalb von Methoden sind lokal und werden nach Ende der Methode gelöscht. Als Attribute bleiben sie erhalten und können von allen Methoden (z. B. auch sonnenuntergang()) verwendet werden.
