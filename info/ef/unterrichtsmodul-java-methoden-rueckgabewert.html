Methoden mit Rückgabewert (return)

In der letzten Stunde haben wir unsere Klasse Rechner mit Übergabeparametern flexibel gemacht und Methoden wie quadrat(a), doppelteEinerZahl(z) oder berechneBrutto(netto) innerhalb von verschiedenes(n) und kbDrucken(netto) aufgerufen. Dabei sind wir auf eine entscheidende Grenze gestoßen: Eine void-Methode druckt ihr Ergebnis lediglich auf die Konsole, liefert aber keinen Wert zurück, mit dem wir weiterrechnen können. Am Beispiel der binomischen Formeln lösen wir genau dieses Problem mit dem Schlüsselwort return.

Zentrales Lernziel Vom reinen Drucker zur echten Rechenfunktion

• Den Unterschied zwischen Ausgeben (System.out.println) und Zurückgeben (return) sicher erklären.
• Methoden mit einem konkreten Rückgabetyp (int, double) statt void deklarieren.
• Rückgabewerte als Bausteine in anderen Methoden auffangen, verrechnen und verschachteln (z. B. binomische Formeln und Kassenbon mit Rabatt).
• Typische Compiler-Fehler rund um Rückgabetyp und return erkennen und beheben.

1 Anknüpfung & die Sackgasse von void (1. Binomische Formel)

Schauen wir zunächst auf das Ende unserer letzten Stunde zurück. In verschiedenes(int n) sollten wir das Quadrat und das Doppelte einer Zahl ausgeben und dafür die vorhandenen Methoden nutzen: 

void doppelteEinerZahl(int z)
{
    System.out.println(2 * z);
}

void quadrat(int a)
{
    System.out.println(a * a);
}

void verschiedenes(int n)
{
    quadrat(n);           // Klappt: druckt n*n direkt auf die Konsole
    doppelteEinerZahl(n); // Klappt: druckt 2*n direkt darunter
}

Solange wir Zahlen nur untereinander ausgeben möchten, funktioniert dieser Baustein-Aufruf problemlos. Jetzt gehen wir einen Schritt weiter und wollen aus genau diesen beiden Bausteinen die 1. binomische Formel zusammensetzen:

1. Binomische Formel als Methoden-Baukasten
$$(a + b)^2 = a^2 + 2 \cdot a \cdot b + b^2$$

$a^2 \rightarrow$ quadrat(a)  •  $2 \cdot a \cdot b \rightarrow$ doppelteEinerZahl(a * b)  •  $b^2 \rightarrow$ quadrat(b)

Versuchen wir nun, diese drei Aufrufe in einer neuen Methode ersteBinomische(int a, int b) zu addieren: 

void ersteBinomische(int a, int b)
{
    int ergebnis = quadrat(a) + doppelteEinerZahl(a * b) + quadrat(b); // COMPILER-FEHLER!
    System.out.println("(a + b)^2 = " + ergebnis);
}
Compiler-Stopp Warum lehnt Java diesen Code sofort ab?

Der Java-Compiler meldet: bad operand types for binary operator '+' bzw. 'void' type not allowed here.

Der Grund: Das Schlüsselwort void bedeutet wörtlich „Leere / Nichts“. Die Methode quadrat(a) ist eine Einbahnstraße: Sie empfängt zwar die Zahl a, schreibt das Quadrat aber nur als Text auf das Konsolenfenster und endet an der schließenden Klammer } mit leeren Händen. Genau das Gleiche passiert bei kbDrucken mit berechneBrutto(netto): kbDrucken kann mit dem Bruttopreis nicht weiterrechnen (z. B. Rabatt abziehen), weil berechneBrutto ihn nur druckt statt zurückzuliefern. Und „Nichts + Nichts + Nichts“ lässt sich nicht addieren!

2 Die Lösung: Rückgabetyp statt void & das Schlüsselwort return

Damit eine Methode wie eine mathematische Funktion arbeitet und ein Ergebnis an ihren Aufrufer zurückliefert, verwandeln wir die Einbahnstraße in einen Kreislauf mit Ausgang:

Bisher: void (Nur Konsolen-Befehl)

void quadrat(int a)
Nimmt den Parameter a durch den Eingangstrichter auf, druckt den Text ins Terminal und liefert nichts zurück.

  • Kopf beginnt mit void.
  • Ergebnis landet als Text in der Konsole.
  • Kann nicht in Rechnungen (+, *) genutzt werden.
Neu: Rückgabetyp + return (Rechenfunktion)

int quadrat(int a)
Ersetzt void durch den Ergebnistyp (int) und sendet das Resultat per return an exakt die Aufrufstelle zurück.

  • Kopf nennt den Typ des Ergebnisses (int, double, ...).
  • return gibt den Wert an den Aufrufer zurück.
  • Kann direkt gespeichert, addiert oder verschachtelt werden.

Bauen wir nun unsere drei Methoden sauber um. Die Rechenmethoden verzichten bewusst auf System.out.println und liefern nur noch ihren Zahlenwert per return zurück: 

// Baustein 1: Liefert das Quadrat als int zurück
int quadrat(int a)
{
    return a * a;
}

// Baustein 2: Liefert das Doppelte als int zurück
int doppelteEinerZahl(int z)
{
    return 2 * z;
}

// Zusammensetzen (Ausführliche Variante mit Zwischenvariablen)
int ersteBinomische(int a, int b)
{
    int teil1 = quadrat(a);                   // fängt a^2 auf
    int teil2 = doppelteEinerZahl(a * b);     // fängt 2*a*b auf
    int teil3 = quadrat(b);                   // fängt b^2 auf
    return teil1 + teil2 + teil3;
}

Sobald die Zwischenschritte klar sind, lässt sich ersteBinomische sogar als eleganter Einzeiler schreiben, weil jeder Methodenaufruf direkt an seiner Stelle durch seinen Rückgabewert ersetzt wird: 

int ersteBinomische(int a, int b)
{
    return quadrat(a) + doppelteEinerZahl(a * b) + quadrat(b);
}
BlueJ-Aha-Effekt Das Methodenergebnis-Fenster in BlueJ

Rufst du auf einem Rechner-Objekt nun per Rechtsklick ersteBinomische(3, 4) auf, öffnet sich nicht mehr das Konsolenfenster, sondern ein kleines Dialogfeld mit der Anzeige int: 49 (Methodenergebnis).
Und die Gegenprobe stimmt auf Anhieb: quadrat(3 + 4) wertet erst 3 + 4 = 7 aus, übergibt 7 an quadrat und liefert ebenfalls 49 zurück!

4 Die 4 Methodentypen & goldene Regeln für return

Mit dem Rückgabewert vervollständigen wir das Gesamtbild aller vier Grundtypen von Methoden in Java:

Typ Eigenschaften Beispiel-Signatur Verwendungszweck
Typ 1 ohne Parameter,
ohne Rückgabe (void)		 void begruessung() Fester Ablauf / starre Ausgabe ohne Eingabedaten.
Typ 2 mit Parameter(n),
ohne Rückgabe (void)		 void kbDrucken(int netto) Führt eine Aktion mit Eingaben aus (z. B. Beleg drucken, Figur bewegen).
Typ 3 ohne Parameter,
mit Rückgabe		 double gibMwStSatz() Liefert einen festen Wert oder später gespeicherte Objekteigenschaften (Getter).
Typ 4 mit Parameter(n),
mit Rückgabe		 int ersteBinomische(int a, int b) Klassische Rechenfunktion: verarbeitet Eingaben und liefert ein Ergebnis weiter.
Regel 1
Typ-Versprechen im Methodenkopf einhalten
Steht im Methodenkopf int, muss hinter return ein ganzzahliger Wert stehen. Steht dort double, wird eine Kommazahl erwartet (ein int wird automatisch zu double erweitert, umgekehrt verbietet Java den Datenverlust von double nach int).
Regel 2
return beendet die Methode sofort
Sobald Java eine return-Anweisung ausführt, wird der Wert nach draußen gereicht und die Methode augenblicklich verlassen. Alle lokalen Variablen sterben dabei im Arbeitsspeicher – nur der Rückgabewert bleibt erhalten.
Regel 3
Rückgabewert auffangen, sonst verpufft er
Ein nackter Aufruf wie quadrat(5); berechnet zwar 25, wirft das Ergebnis aber ungenutzt weg. Sinnvoll sind drei Wege: in einer Variable speichern (int q = quadrat(5);), direkt weiterrechnen (quadrat(5) + 10) oder direkt übergeben (System.out.println(quadrat(5));).
Regel 4
Rechnen und Ausgeben sauber trennen
Gute Software trennt Berechnung (return) und Darstellung (System.out.println). So kann berechneBrutto(netto) sowohl von kbDrucken als auch von einer späteren Rabatt-Methode wiederverwendet werden.
Typische Fehlerquellen Drei klassische Compiler-Fehler beim Einstieg in return

1. Rückgabe in einer void-Methode: Wer void schreibt, hat „keine Rückgabe“ versprochen. Ein return a * a; erzeugt den Fehler incompatible types: unexpected return value.

2. Unerreichbarer Code nach return: Schreibt man unter return ergebnis; noch ein System.out.println(...);, bricht der Compiler mit unreachable statement ab – diese Zeile wird niemals erreicht.

3. Rückgabe vergessen: Hat die Methode einen Rückgabetyp wie int, aber es fehlt das return, meldet Java missing return statement.

MERKE

1. Methoden mit Rückgabewert (return)

• Soll eine Methode ein Ergebnis an den Aufrufer zurückliefern, ersetzt man void im Methodenkopf durch den passenden Rückgabetyp (z. B. int oder double).
• Mit return wert; wird das Ergebnis an die exakte Aufrufstelle zurückgegeben. Gleichzeitig wird die Methode sofort beendet.
• Der Datentyp des zurückgegebenen Werts muss zum Rückgabetyp im Methodenkopf passen.

2. Ausgeben vs. Zurückgeben

• System.out.println(...) schreibt nur Text für den Menschen auf die Konsole – das Programm kann damit nicht weiterrechnen.
• return ... liefert einen echten Datenwert an das Programm zurück. Diesen kann man in einer Variable speichern (int erg = quadrat(3);), direkt in Termen addieren oder als Argument an die nächste Methode weiterreichen.
