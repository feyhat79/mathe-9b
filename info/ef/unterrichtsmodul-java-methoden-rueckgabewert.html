Methoden mit Rückgabewert & das Schlüsselwort `return`

Bisher haben all unsere Methoden mit dem Schlüsselwort void geendet: Sie führten Befehle aus und druckten Ergebnisse mit System.out.println auf die Konsole. Doch was passiert, wenn ein anderes Programmteil mit dem Ergebnis einer Methode weiterrechnen möchte? In dieser Lerneinheit lüften wir das Geheimnis des Rückgabewerts. Wir klären die entscheidende Frage: Wann braucht eine Methode void und wann einen konkreten Datentyp? Und wir lernen das Schlüsselwort return kennen, das Werte an den Aufrufer zurückliefert.

Zentrales Lernziel Vom Konsolen-Drucker zum echten Wert-Lieferanten (EVA-Prinzip)

• Den fundamentalen Unterschied zwischen einer Konsolenausgabe (Nebeneffekt) und einem Rückgabewert (echter Datenwert) verstehen.
• Sicher entscheiden können, ob eine Methode void sein muss oder einen Datentyp benötigt.
• Das Schlüsselwort return syntaktisch fehlerfrei einsetzen und Ergebnisse im Code weiterverarbeiten.

1 Das Kernproblem: Tote Pixel vs. lebendige Daten

Stell dir vor, du gehst in einen Supermarkt. An der Kasse fragst du nach dem Gesamtpreis. Die Kassiererin ruft den Betrag laut in den Raum: „15 Euro!“ – aber das Kassensystem verweigert die Übergabe der Zahl an das Kartenterminal. Du kannst nicht bezahlen, weil der Betrag nur als Schallwelle im Raum verhallt ist, statt digital an das Bezahlgerät übergeben zu werden!

Genau dieses Problem haben wir bisher in Java mit void erzeugt: 

// Version A: void (Die Methode druckt nur etwas auf den Bildschirm)
void berechneMehrwertsteuerDrucken(double netto) 
{
    double mwst = netto * 0.19;
    System.out.println("MwSt: " + mwst + " €"); 
    // Der Wert 'mwst' verpufft als tote Pixel auf der Konsole!
}

Möchte ein Online-Shop nun den Brutto-Endpreis berechnen, scheitert der Programmierer kläglich: 

double netto = 100.0;
// FEHLER BEIM KOMPILIEREN!
double brutto = netto + rechner.berechneMehrwertsteuerDrucken(netto);
// Fehlermeldung: 'void' type not allowed here!

Die Lösung mit return: Wir ersetzen void durch den Datentyp des Ergebnisses (double). Mit dem Befehl return übergeben wir das Rechenergebnis direkt in die Hand des Aufrufers: 

// Version B: Mit Rückgabewert (double) – Das echte EVA-Prinzip
double berechneMehrwertsteuer(double netto) 
{
    double mwst = netto * 0.19;
    return mwst; // Liefert die Zahl 19.0 an den Aufrufer zurück!
}

Jetzt kann das Hauptprogramm problemlos mit dem Wert weiterrechnen: double brutto = netto + rechner.berechneMehrwertsteuer(netto); ergibt sauber 119.0.

BlueJ-Aha-Effekt Das rote Ergebnis-Dialogfenster

Wenn du in BlueJ mit der rechten Maustaste eine Methode mit Rückgabewert aufrufst (z. B. addiere(17, 4)), öffnet BlueJ ein rotes Dialogfenster mit der Aufschrift: int result: 21. Das beweist: Das Ergebnis ist kein Text auf der Konsole, sondern ein echter Wert im Speicher!

3 Die Gesetze des `return`-Befehls

Beim Einsatz von Rückgabewerten gelten in Java drei unumstößliche Regeln:

Regel 1
Typ-Treue (Der Vertrag im Methodenkopf)
Der im Methodenkopf versprochene Rückgabetyp muss exakt zum Typ des Werts hinter return passen. Verspricht der Kopf int, darf kein double oder String zurückgegeben werden.
Regel 2
Sofortiges Methoden-Ende (*Unreachable Code*)
Sobald Java die Zeile mit return ...; ausführt, wird die Methode augenblicklich beendet. Programmcode, der hinter einem return steht, wird niemals erreicht – der Compiler meldet einen Fehler (*unreachable code*).
Regel 3
Der Rückgabewert ist wie eine Zahl im Code einsetzbar
Ein Methodenaufruf mit Rückgabewert verhält sich wie die Zahl selbst: Du kannst ihn in einer Variablen ablegen (int s = r.addiere(5, 3);) oder direkt in Rechnungen einbinden (int dop = r.addiere(5, 3) * 2;).

4 Die Klasse `Rechner.java` (Teil 3 in Aktion)

Hier sind die neuen Methoden mit Rückgabewerten, wie sie in unserer Klasse angelegt sind: 

public class Rechner 
{
    // ==============================================================
    // BEISPIEL: Rückgabetyp double statt void
    // ==============================================================
    double berechneMehrwertsteuer(double netto)
    {
        double mwst = netto * 0.19;
        return mwst; // Gibt den Wert an den Aufrufer zurück
    }

    // ==============================================================
    // BEISPIEL 2: Kompakte Addition zweier Ganzzahlen
    // ==============================================================
    int addiere(int a, int b)
    {
        return a + b; // Berechnung und Rückgabe in einer Zeile!
    }

    // ==============================================================
    // BEISPIEL 3: Nur den Divisionsrest liefern
    // ==============================================================
    int restSekunden(int gesamtSekunden)
    {
        return gesamtSekunden % 60;
    }
}

MERKE

1. Rückgabetyp vs. void

• `void`: Die Methode führt eine Aktion aus (z. B. Konsolenausgabe, Zeichnen, Zustand ändern), liefert aber keinen Datenwert zurück.
• Datentyp (`int`, `double`, `boolean`, `String`): Die Methode berechnet einen Wert oder beantwortet eine Frage und übergibt das Resultat mit return an den Aufrufer.

2. Der Befehl `return`

• return wert; liefert den berechneten Wert zurück und beendet die Methode sofort.
• Der gelieferte Wert muss exakt zum Typ im Methodenkopf passen.
• Mit dem Rückgabewert kann im aufrufenden Code direkt weitergerechnet oder er kann in einer Variablen gespeichert werden.
