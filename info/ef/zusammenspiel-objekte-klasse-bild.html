Zusammenspiel von Objekten & Die Klasse Bild

Vom mühsamen Mausklick auf der Werkbank zur automatisierten Programmierung: Wir schärfen den Unterschied zwischen Konstruktor und Objekt und lassen mehrere Figuren in einer neuen Klasse zusammenarbeiten.

1

Der Dreiklang: Klasse, Konstruktor und Objekt

In der objektorientierten Programmierung kommt es bei Einsteigern häufig zu einer Verwechslung: „Ist der Konstruktor nicht einfach das Objekt?“ Nein! Um sauberen Programmcode schreiben zu können, müssen wir diese drei Grundbegriffe absolut trennscharf beherrschen:

1. Bauplan Klasse

Was ist es? Der statische Quelltext im Editor (Kreis.java).

Sie definiert abstrakt, welche Attribute (z. B. Farbe, Größe) und welche Methoden alle Exemplare dieser Art besitzen werden. Sie verbraucht keinen Platz im Spiel- oder Zeichenbereich.

2. Geburtsstunde Konstruktor

Was ist es? Die Initialisierungs-Routine in der Klasse (public Kreis()).

Wird genau einmal im Moment der Entstehung aufgerufen. Er weist dem neuen Ding seine Startwerte zu (Startfarbe, Startposition). Der Konstruktor ist die Fabrikaktion, nicht das fertige Ding!

3. Einzelstück Objekt (Instanz)

Was ist es? Das lebendige Exemplar im Arbeitsspeicher (rote Box in BlueJ).

Es besitzt einen konkreten, veränderlichen Zustand und eine eigene Identität. Aus einer einzigen Klasse können Hunderte verschiedene Objekte gebaut werden.

MERKE
Der Unterschied auf den Punkt gebracht
Ein Konstruktor ist eine spezielle Anweisung zur Erschaffung eines Objekts. Das Objekt ist das lebendige Ergebnis dieser Erschaffung. Man kann ein fertiges Objekt steuern, aber man kann dessen Konstruktor nicht nachträglich ein zweites Mal aufrufen – ein Lebewesen wird schließlich auch nur einmal geboren!

Analogie A: Rollenspiel (Gaming)

Der Charakter-Editor

  • Klasse: Der Code für die Charakterklasse Magier im Spielverzeichnis.

  • Objekt: Das zugelassene Auto mit Kennzeichen DO-EF-2026 auf dem Schulparkplatz mit eigenem Kilometerstand.

Das Grundproblem: Das Klick-Dilemma

Kognitiver Konflikt: Die Grenzen der Werkbank

In den vergangenen Stunden haben wir ein einfaches Haus (Wand, Fenster, Dach und Sonne) gebaut. Dazu musstest du über 25-mal mit der rechten Maustaste klicken, Namen eingeben, Methoden aufrufen und Koordinaten eintippen.

Das Problem: Sobald du BlueJ neu startest oder das Projekt zurücksetzt, ist die gesamte Zeichnung verschwunden! Niemand möchte jedes Mal 25 manuelle Aktionen wiederholen.

Die didaktische Leitfrage:

Wie bringen wir dem Computer bei, diese 25 Schritte auf einen einzigen Knopfdruck selbstständig im Quelltext auszuführen?

Anatomie der Java-Syntax

1. Die Objekterzeugung im Quelltext zerlegt:

Quadrat wand = new Quadrat();

Quadrat Datentyp (Klasse): Welcher Typ von Objekt soll hier referenziert werden?

wand Bezeichner (Name): Unter welchem Namen können wir das Objekt ansprechen?

new Operator: Befehl an Java, im Arbeitsspeicher Platz für ein neues Objekt zu schaffen.

Quadrat() Konstruktor: Initialisiert das neue Objekt mit Standardwerten.

2. Die Punktnotation: Objekte steuern:

wand . groesseAendern( 120 );

Der Punkt (.) ist das wichtigste Steuerzeichen: Er bedeutet „Greife auf dieses konkrete Objekt zu und führe dessen Methode aus!“.

1

Das Konzept der Komposition: „Hat-ein“-Beziehung

Statt alle Figuren lose auf der Werkbank herumliegen zu lassen, schaffen wir ein übergeordnetes Steuerungsobjekt: Eine neue Klasse namens Bild.

Die logische Beziehung:

Ein Objekt der Klasse Bild ist selbst kein Kreis und kein Quadrat. Aber das Bild „hat ein“ Quadrat (Wand), „hat ein“ Dreieck (Dach), „hat ein“ zweites Quadrat (Fenster) und „hat einen“ Kreis (Sonne)!

In der Informatik nennt man dies Komposition (bzw. Assoziation). Das Bild besitzt Referenzen auf seine Einzelteile.

2

Schritt-für-Schritt: Die Klasse Bild in BlueJ erstellen

  1. Neue Klasse anlegen: Klicke im BlueJ-Hauptfenster auf den Button „Neue Klasse...“. Vergib als Klassennamen exakt: Bild (Großgeschrieben, keine Leerzeichen).
  2. Editor öffnen: Mache einen Doppelklick auf die neue gelb-schraffierte Kachel Bild. Lösche den vorgegebenen Beispielcode im Editor vollständig (Strg + A $\rightarrow$ Entf).
  3. Attribute deklarieren: Schreibe die Referenzen auf die vier Figuren als private Attribute ganz oben in die Klasse.
  4. Konstruktor schreiben: Erzeuge im Konstruktor public Bild() die vier Objekte mit new.
  5. Methode zeichne() definieren: Rufe an den Objekten die Positionierungs- und Färbemethoden auf und mache sie am Ende sichtbar.
  6. Kompilieren: Klicke auf „Übersetzen“ (Compile). Achte darauf, wie BlueJ nun automatisch gestrichelte Pfeile zu den Figuren zeichnet!

Der fertige Quelltext zum Nachvollziehen: 

/**
 * Ein Bild, das aus mehreren geometrischen Figuren zusammengesetzt ist.
 */
public class Bild {

    // --- 1. Attribute: Das Bild besitzt Referenzen auf Figuren ---
    private Quadrat wand;
    private Dreieck dach;
    private Quadrat fenster;
    private Kreis   sonne;

    /**
     * Konstruktor: Hier werden alle Figuren im Speicher erzeugt!
     */
    public Bild() {
        wand = new Quadrat();
        dach = new Dreieck();
        fenster = new Quadrat();
        sonne = new Kreis();
    }

    /**
     * Zeichnet die Gesamtszene auf Knopfdruck auf die Leinwand.
     */
    public void zeichne() {
        // 1. Wand einrichten
        wand.groesseAendern(120);
        wand.farbeAendern("rot");
        wand.horizontalBewegen(-50);
        wand.vertikalBewegen(80);
        wand.sichtbarMachen();

        // 2. Fenster einrichten
        fenster.farbeAendern("schwarz");
        fenster.groesseAendern(35);
        fenster.horizontalBewegen(-15);
        fenster.vertikalBewegen(120);
        fenster.sichtbarMachen();

        // 3. Dach einrichten
        dach.farbeAendern("gruen");
        dach.groesseAendern(60, 150);
        dach.horizontalBewegen(20);
        dach.vertikalBewegen(45);
        dach.sichtbarMachen();

        // 4. Sonne einrichten
        sonne.farbeAendern("gelb");
        sonne.groesseAendern(65);
        sonne.horizontalBewegen(125);
        sonne.vertikalBewegen(-30);
        sonne.sichtbarMachen();
    }
}

Praxis-Herausforderung: Eigene Methoden programmieren

Wenn dein Bild funktioniert, erweitere die Klasse um interaktive Animationen und Szenenwechsel:

Aufgabe A: Sonnenuntergang

Programmiere eine neue Methode public void sonnenuntergang(). Die Sonne soll langsam nach unten wandern (langsamVertikalBewegen(250)) und anschließend ihre Farbe in Blau ändern.

Musterlösung für Aufgabe A ansehen: 
public void sonnenuntergang() {
    sonne.langsamVertikalBewegen(250);
    sonne.farbeAendern("blau");
}
Aufgabe B (Zusatz): Nacht-Modus

Programmiere eine Methode public void nachtModus(): Die Sonne verschwindet (unsichtbarMachen()), die Wand wird dunkelblau und im Fenster geht das Licht an (Farbe ändert sich zu "gelb")!

Musterlösung für Aufgabe B ansehen: 
public void nachtModus() {
    sonne.unsichtbarMachen();
    wand.farbeAendern("blau");
    fenster.farbeAendern("gelb");
}

Merkhefteintrag: Die Kernkonzepte zum Abschreiben

MERKE
Zusammenfassung: Konstruktor, Objekterzeugung & Punktnotation

1. Klasse vs. Konstruktor vs. Objekt:
• Klasse: Der Bauplan / Typ im Quelltext.
• Konstruktor: Die Initialisierungsroutine in der Klasse. Heißt exakt wie die Klasse und wird genau einmal bei der Erschaffung aufgerufen.
• Objekt: Das konkrete Exemplar im Arbeitsspeicher mit eigenem Zustand.

2. Objekterzeugung mit new:
Die Syntax zur Erzeugung eines Objekts im Quelltext lautet:
Klassenname objektName = new Klassenname();
Der new-Operator reserviert Speicherplatz und ruft den Konstruktor auf.

3. Die Punktnotation:
Um ein Objekt zu steuern, sendet man ihm über den Punkt eine Botschaft:
objektName.methodenName(parameterWert);

4. Komposition („Hat-ein“-Beziehung):
Ein komplexes Objekt kann andere Objekte als Attribute besitzen und steuern. Im BlueJ-Klassendiagramm wird diese Abhängigkeit durch einen gestrichelten Pfeil dargestellt.

2

Abschluss-Reflexion: Detektiv-Fragen

Frage 1: Warum stehen die Variablen dach, wand, sonne außerhalb der Methode zeichne(), ganz oben in der Klasse?
Weil sie Attribute des Bildes sind! Wenn sie innerhalb einer Methode deklariert würden, wären sie lokale Variablen und würden nach Ende der Methode sofort aus dem Speicher gelöscht. Als Attribute bleiben sie dauerhaft im Bild-Objekt erhalten, sodass auch spätere Methoden wie sonnenuntergang() auf dieselbe Sonne zugreifen können.
Frage 2: Was passiert, wenn man im Konstruktor Bild() die Zeile sonne = new Kreis(); vergisst, aber in zeichne() sonne.sichtbarMachen(); aufruft?
Java stürzt mit einer NullPointerException ab! Die Referenzvariable sonne hat dann den Standardwert null (sie zeigt ins Leere). Wenn man versucht, an einem nicht existierenden Objekt eine Methode aufzurufen, weiß Java nicht, wohin der Befehl geschickt werden soll.
Frage 3: Woran erkennt man im Quelltext sofort, dass eine Methode der Konstruktor ist?
An zwei Merkmalen: 1. Der Konstruktor heißt haargenau wie die Klasse (z. B. public Bild() in der Klasse Bild). 2. Er besitzt keinen Rückgabetyp – nicht einmal das Schlüsselwort void darf davor stehen!
