1 Phase 1: Der Code-Detektiv – Warum bleibt die Leinwand weiß?

Ein Schüler hat begonnen, die Klasse Auto zu programmieren. Klickt er in BlueJ auf „Übersetzen“, meldet der Compiler zwar keine Syntaxfehler – erzeugt er jedoch ein Objekt auf der Werkbank und ruft die Methode auf, erscheint absolut nichts auf der Leinwand! Öffnet man zudem per Rechtsklick den Objekt-Inspektor, steht bei allen Variablen enttäuschend <null>.

Der aktuelle Quelltext in Auto.java: 

public class Auto {

    // Attribute der Klasse Auto
    Quadrat tuer1; 
    Quadrat tuer2; 
    Quadrat dach; 
    Kreis   reifenLinks; 
    Kreis   reifenRechts; 
    
    void zeichen() {
        Quadrat tuer1 = new Quadrat(); 
        Quadrat tuer2 = new Quadrat();
        Quadrat dach = new Quadrat();
        Kreis reifenLinks = new Kreis();
        Kreis reifenRechts = new Kreis();
    }
}
Diagnose-Aufgabe

Finde die drei grundlegenden Fehler in diesem Entwurf, bevor du eine einzige Zeile korrigierst. Überlege zuerst selbst, bevor du die Analyse-Karten aufdeckst!

Detektiv-Frage A: Warum steht im Objekt-Inspektor überall <null>, obwohl new Quadrat() ausgeführt wurde?
Das Problem der Schattenvariablen (Variable Shadowing):
In Zeile 10 steht: Quadrat tuer1 = new Quadrat();.
Durch die Wiederholung des Datentyps Quadrat wird eine neue, lokale Variable erzeugt, die nur innerhalb der geschweiften Klammern von zeichen() existiert! Sie verdeckt („beschattet“) das eigentliche Attribut ganz oben.
Sobald die Methode beendet ist, wird die lokale Variable im Arbeitsspeicher vernichtet. Das dauerhafte Attribut tuer1 der Klasse Auto blieb unberührt und zeigt weiterhin auf null!

Richtige Zuweisung an das Attribut:
tuer1 = new Quadrat(); (ohne nochmaligen Datentyp vorneweg!).
Detektiv-Frage B: Warum gehört die Objekterzeugung mit new in einen Konstruktor und nicht in eine Zeichenmethode?
Lebenszyklus von Objekten:
Ein Auto wird in der Fabrik genau einmal zusammengebaut (im Konstruktor public Auto()). Würde man die Teile in einer Zeichenmethode erzeugen, würde bei jedem Neuzeichnen ein komplett neuer Satz Reifen und Türen im Speicher reserviert werden. Zudem sollte ein Auto nach dem Erschaffen sofort einsatzbereit sein.
Detektiv-Frage C: Was fehlt im Quelltext völlig, damit auf dem Bildschirm ein echtes Auto zu sehen ist?
Zustand und Positionierung:
1. Alle Figuren sind nach dem Aufruf von new standardmäßig unsichtbar. Es fehlt für jedes Teil der Aufruf sichtbarMachen().
2. Alle Teile liegen momentan an ihren Standardkoordinaten übereinander. Sie müssen mit horizontalBewegen(...) und vertikalBewegen(...) zu einem echten Fahrzeug zusammengesetzt werden.
3. Auch der Methodenname enthält einen Tippfehler: zeichen() statt zeichne().

  2. Schreibe den Konstruktor public Auto(): Erzeuge alle 5 Objekte mit new und setze istGezeichnet = false;.

Selbstkontrolle: Quelltext-Musterlösung für Konstruktor, zeichne() und loesche() ansehen 
public class Auto {

    // 1. Attribute: Das Auto besitzt 5 grafische Teilobjekte ("Hat-ein"-Beziehung)
    private Quadrat tuer1;
    private Quadrat tuer2;
    private Quadrat dach;
    private Kreis   reifenLinks;
    private Kreis   reifenRechts;
    private boolean istGezeichnet;

    /**
     * Konstruktor: Baut das Auto im Arbeitsspeicher zusammen.
     */
    public Auto() {
        tuer1 = new Quadrat();
        tuer2 = new Quadrat();
        dach = new Quadrat();
        reifenLinks = new Kreis();
        reifenRechts = new Kreis();
        istGezeichnet = false;
    }

    /**
     * Richtet alle Figuren passend aus und macht das Auto sichtbar.
     */
    public void zeichne() {
        if (!istGezeichnet) {
            // 1. Karosserie links
            tuer1.groesseAendern(50);
            tuer1.farbeAendern("rot");
            tuer1.horizontalBewegen(40);
            tuer1.vertikalBewegen(60);
            tuer1.sichtbarMachen();

            // 2. Karosserie rechts
            tuer2.groesseAendern(50);
            tuer2.farbeAendern("rot");
            tuer2.horizontalBewegen(90);
            tuer2.vertikalBewegen(60);
            tuer2.sichtbarMachen();

            // 3. Dach (Fahrerkabine)
            dach.groesseAendern(40);
            dach.farbeAendern("blau");
            dach.horizontalBewegen(65);
            dach.vertikalBewegen(20);
            dach.sichtbarMachen();

            // 4. Räder
            reifenLinks.groesseAendern(30);
            reifenLinks.farbeAendern("schwarz");
            reifenLinks.horizontalBewegen(-100);
            reifenLinks.vertikalBewegen(150);
            reifenLinks.sichtbarMachen();

            reifenRechts.groesseAendern(30);
            reifenRechts.farbeAendern("schwarz");
            reifenRechts.horizontalBewegen(-50);
            reifenRechts.vertikalBewegen(150);
            reifenRechts.sichtbarMachen();

            istGezeichnet = true;
        }
    }

    /**
     * Entfernt das gesamte Auto von der Leinwand.
     */
    public void loesche() {
        if (istGezeichnet) {
            tuer1.unsichtbarMachen();
            tuer2.unsichtbarMachen();
            dach.unsichtbarMachen();
            reifenLinks.unsichtbarMachen();
            reifenRechts.unsichtbarMachen();
            istGezeichnet = false;
        }
    }
}

/**
 * Bewegt das gesamte Auto um die angegebene Strecke nach rechts.
 * @param distanz Die zurueckzulegende Distanz in Pixeln
 */
public void nachRechtsFahren(int distanz) {
    if (istGezeichnet) {
        tuer1.horizontalBewegen(distanz);
        tuer2.horizontalBewegen(distanz);
        dach.horizontalBewegen(distanz);
        reifenLinks.horizontalBewegen(distanz);
        reifenRechts.horizontalBewegen(distanz);
    }
}

/**
 * Bewegt das gesamte Auto um die angegebene Strecke nach links.
 */
public void nachLinksFahren(int distanz) {
    nachRechtsFahren(-distanz); // Wiederverwendung mit negativem Vorzeichen!
}

/**
 * Aendert die Lackierung der Karosserie in eine neue Wunschfarbe.
 * @param neueFarbe Z.B. "blau", "gelb", "schwarz", "gruen"
 */
public void lackieren(String neueFarbe) {
    if (istGezeichnet) {
        tuer1.farbeAendern(neueFarbe);
        tuer2.farbeAendern(neueFarbe);
    }
}
4 Phase 4: Experten-Werkstatt – Herausforderungen für Schnelle

Du bist bereits mit Phase 1 bis 3 fertig und dein Auto fährt zuverlässig? Wähle mindestens zwei der folgenden Meister-Aufgaben und baue dein Fahrzeug zu einem Spezialmodell aus!

Level 1: Das Einsatzfahrzeug (Blaulicht)
Programmiere eine Methode public void blaulicht().
Das Dach soll die Farbe zu "blau" wechseln. Wenn du die Leinwand-Pause nutzt (Leinwand.getLeinwand().warte(250)), kannst du das Dach zwischen Blau und Rot blinken lassen!

Level 2: Das Cabriolet (Dach abnehmen)
Programmiere zwei Methoden:
• public void dachOeffnen(): Macht nur das Dach unsichtbar.
• public void dachSchliessen(): Macht das Dach wieder sichtbar. 
public void dachOeffnen() {
    dach.unsichtbarMachen();
}
public void dachSchliessen() {
    dach.sichtbarMachen();
}
Level 3: Zweiter Konstruktor mit Lackierung
In Java kann eine Klasse mehrere Konstruktoren besitzen (Überladung).
Schreibe einen zweiten Konstruktor:
public Auto(String startFarbe)
Erzeuge auch hier alle fünf Teile mit new, färbe aber die Türen direkt in der Wunschfarbe ein!
Rufe im neuen Konstruktor einfach this(); auf (ruft den Standardkonstruktor auf) und führe danach lackieren(startFarbe); aus!
Level 4: Zwei Autos auf der Werkbank
Erzeuge in BlueJ zwei unterschiedliche Objekte:
auto1 = new Auto(); und auto2 = new Auto();.
Zeichne beide Autos. Verschiebe eines nach unten (hebeBühne(80)) und lackiere es gelb. Lasse beide unabhängig voneinander fahren!
Programmiere in Auto eine Hilfsmethode public void vertikalVersetzen(int deltaY), damit das zweite Auto auf eine zweite Fahrspur gesetzt werden kann.
5 Phase 5: Merkheft-Sicherung & Wissens-TÜV

Sichere die wichtigsten Erkenntnisse der heutigen Doppelstunde in deinem Merkheft bzw. deiner OneNote-Mappe.

MERKE
Die 4 Kernregeln der Objektorientierten Komposition („Hat-ein“-Beziehung)

1. Komposition im Quelltext:
Ein zusammengesetztes Objekt (z. B. ein Auto) besitzt andere Objekte als Attribute. Im BlueJ-Klassendiagramm wird diese Abhängigkeit durch gestrichelte Pfeile dargestellt.

2. Erzeugung im Konstruktor:
Die Teilobjekte werden im Konstruktor der übergeordneten Klasse mit dem Schlüsselwort new erschaffen. Der Konstruktor heißt haargenau wie die Klasse und besitzt keinen Rückgabetyp.

3. Niemals Datentypen in Methoden wiederholen:
Schreibt man in einer Methode Quadrat tuer1 = new Quadrat();, erzeugt man eine kurzlebige Schattenvariable. Das Attribut bleibt null! Richtig ist die reine Zuweisung an das bestehende Attribut: tuer1 = new Quadrat();.

4. Delegieren über Punktnotation:
Um das Gesamtsystem zu steuern, sendet die Hauptklasse über den Punkt Befehle an ihre Teilobjekte (tuer1.horizontalBewegen(distanz);). Jedes Teilobjekt behält dabei seinen eigenen Zustand.

Abschluss-TÜV: Teste dein Verständnis

Frage 1: Was würde passieren, wenn man im Konstruktor Auto() die Zeile reifenLinks = new Kreis(); löscht und dann zeichne() aufruft?
Das Programm stürzt mit einer NullPointerException ab! Weil die Variable reifenLinks dann den Standardwert null besitzt, kann Java den Befehl sichtbarMachen() an kein reales Objekt im Speicher übermitteln.
Frage 2: Warum kann man einem Objekt der Klasse Auto nicht direkt den Befehl auto1.sichtbarMachen() schicken?
Weil die Klasse Auto keine Methode namens sichtbarMachen() besitzt! Nur die Basisfiguren (Quadrat, Kreis, Dreieck) kennen diese Methode direkt. Die Klasse Auto hat dafür ihre eigene Methode zeichne(), die die Sichtbarkeit ihrer Teilfiguren intern steuert.
Frage 3: Welchen großen Vorteil hat es, Methoden wie nachRechtsFahren(int distanz) mit einem Parameter zu programmieren?
Maximale Flexibilität: Statt für jede Schrittweite eine feste Methode schreiben zu müssen (fahre10(), fahre20()), kann der Aufrufer frei bestimmen, wie weit das Auto rollt (z. B. nachRechtsFahren(150)). Zudem kann man durch Übergabe eines negativen Werts (-50) sofort rückwärts fahren!
