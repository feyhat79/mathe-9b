Methodensignaturen & Übergabeparameter

Bisher waren unsere Java-Methoden starre Ausführer: Sie arbeiteten mit fest im Quellcode einprogrammierten Zahlen (z. B. starr 145 Sekunden in zeitUmrechnen()). Wollte man eine andere Zahl berechnen, musste man den Quelltext umschreiben und neu kompilieren. In dieser Lerneinheit machen wir unsere Methoden flexibel und ansprechbar: Wir lernen das Konzept der Übergabeparameter kennen und untersuchen genau, wann diese Variablen im Arbeitsspeicher entstehen, wo sie leben und warum sie an der schließenden Klammer wieder spurlos verschwinden.

Zentrales Lernziel Vom starren Arbeiter zum flexiblen Assistenten

• Methoden deklarieren, die Eingabewerte über die runden Klammern (int zahl) entgegennehmen.
• Den fundamentalen Unterschied zwischen Parameter (Schablone) und Argument (konkreter Wert) sicher anwenden.
• Den Lebenszyklus (Geburt, Gültigkeitsbereich, Tod) lokaler Parameter im Arbeitsspeicher präzise erklären.

1 Das Problem: Der starre Rechner

Betrachten wir die Methode zeitUmrechnen() aus unserer bisherigen Klasse Rechner.java: 

// Bisheriger Zustand: Starr und unflexibel
void zeitUmrechnen()
{
    int gesamtSekunden = 145; // Fest verdrahteter Wert!
    int minuten = gesamtSekunden / 60;
    int restSekunden = gesamtSekunden % 60;
    System.out.println(gesamtSekunden + " s sind " + minuten + " min und " + restSekunden + " s.");
}

Der Mangel: Diese Methode rechnet jedes Mal stur 145 Sekunden um. Ein echter Taschenrechner muss jedoch mit jeder beliebigen Zahl rechnen können, die ihm der Nutzer beim Start zur Verfügung stellt.

Die Lösung: Wir verlegen die Variablendeklaration direkt in die runden Klammern des Methodenkopfs: 

// Neu: Flexibel durch Übergabeparameter
void zeitUmrechnenFlexibel(int gesamtSekunden)
{
    int minuten = gesamtSekunden / 60;
    int restSekunden = gesamtSekunden % 60;
    System.out.println(gesamtSekunden + " s sind " + minuten + " min und " + restSekunden + " s.");
}
BlueJ-Aha-Effekt Was passiert beim Methodenaufruf?

Wenn du in BlueJ mit der rechten Maustaste auf ein erzeugtes Objekt klickst und zeitUmrechnenFlexibel(gesamtSekunden) auswählst, öffnet sich ein Eingabedialog. Hier tippst du z. B. 350 ein. Java weist diesen Wert automatisch dem Parameter gesamtSekunden zu und startet die Rechnung!

2 Fachbegriffe: Parameter vs. Argument

In der Informatik wird streng zwischen der Schablone im Quelltext und dem konkreten Wert beim Ausführen unterschieden:

Fachbegriff Wo steht er? Bedeutung & Beispiel
Parameter
(formaler Parameter)		 Im Methodenkopf
void quadriere(int zahl)		 Der Platzhalter / Trichter. Er legt fest, welcher Datentyp hineingeworfen werden muss und unter welchem Namen er im Methodenrumpf ansprechbar ist.
Argument
(aktueller Parameter)		 Beim Methodenaufruf
r.quadriere(7);		 Der konkrete Wert, der tatsächlich an die Methode übergeben wird. Hier ist die Zahl 7 das Argument.

3 Lebensdauer & Gültigkeitsbereich (*Scope & Lifetime*)

Ein Parameter ist eine lokale Variable. Seine Existenz im Arbeitsspeicher (RAM) ist streng an den Ablauf seiner eigenen Methode gekoppelt:

1. Geburt
Aufruf der Methode (Öffnende geschweifte Klammer `{`)
Java reserviert im Arbeitsspeicher (auf dem Stack) ein Speicherfach für den Parameter. Der übergebene Argument-Wert wird hineinkopiert.
2. Leben
Innerhalb des Methodenrumpfs
Der Parameter kann gelesen, in Rechnungen genutzt und verändert werden. Wichtig: Nur diese eine Methode kann ihn sehen (Gültigkeitsbereich).
3. Tod
Ende der Methode (Schließende geschweifte Klammer `}`)
Sobald die schließende Klammer } erreicht wird, wird das Speicherfach **spurlos aus dem RAM gelöscht**. Der Parameter existiert nicht mehr!
Zwei typische Fehlerquellen Was Schüler häufig falsch machen

Fehler 1: Doppel-Deklaration
Weil der Parameter bereits im Kopf deklariert ist (void rechne(int x)), darf im Rumpf nicht noch einmal int x = 10; stehen. Das führt zum Compiler-Fehler: variable x is already defined.

Fehler 2: Fernzugriff über Methodengrenzen hinweg
Eine Methode B kann niemals auf den Parameter von Methode A zugreifen. Variablen „wandern“ nicht von selbst durch die Klasse!

4 Die erweiterte Klasse `Rechner.java`

Hier ist die vollständige Version der Klasse mit Beispielen für einen Parameter, zwei Parameter und verschiedene Datentypen: 

public class Rechner 
{
    // ==============================================================
    // BEISPIEL 1: Ein Parameter (Ganzzahl)
    // ==============================================================
    void quadriere(int zahl) 
    {
        int ergebnis = zahl * zahl;
        System.out.println("Das Quadrat von " + zahl + " ist: " + ergebnis);
    } // <-- HIER sterben 'zahl' und 'ergebnis' im RAM!

    // ==============================================================
    // BEISPIEL 2: Zwei Parameter (durch Komma getrennt)
    // ==============================================================
    void rechteckFlaeche(int breite, int laenge) 
    {
        int flaeche = breite * laenge;
        System.out.println("Rechteck (" + breite + " x " + laenge + ") hat die Fläche: " + flaeche);
    }

    // ==============================================================
    // BEISPIEL 3: Verschiedene Datentypen kombinieren (String & int)
    // ==============================================================
    void druckeKassenbon(String artikel, int anzahl, int preisCent) 
    {
        int gesamtCent = anzahl * preisCent;
        System.out.println("Artikel: " + artikel);
        System.out.println("Menge:   " + anzahl + " x " + preisCent + " Cent");
        System.out.println("Gesamt:  " + gesamtCent + " Cent");
    }
}

MERKE

1. Parameter & Argument

• Der Parameter steht im Methodenkopf (z. B. void methode(int zahl)). Er fungiert als Trichter/Platzhalter.
• Das Argument ist der tatsächliche Wert, der beim Aufruf übergeben wird (z. B. r.methode(15);).
• Mehrere Parameter werden innerhalb der Klammern mit einem Komma getrennt (int a, int b).

2. Lebensdauer & Gültigkeitsbereich

• Parameter sind lokale Variablen: Sie werden beim Methodenaufruf im Arbeitsspeicher (RAM) erzeugt und beim Erreichen der schließenden Klammer } unwiderruflich gelöscht.
• Andere Methoden haben keinen Zugriff auf fremde Parameter.
• Ein Parameter darf im Rumpf nicht noch einmal deklariert werden (kein doppeltes int).
