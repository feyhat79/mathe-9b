Das Binärsystem, Stellenwerttafel & Umrechnungsmethoden

Vom Schalterzustand (Bit) zum Byte: Stellenwerttafel und Divisionsalgorithmus mit Rest

1 Grundlagen: Das Bit und das Verdopplungsprinzip

Computer kennen physikalisch nur zwei Schaltzustände: Strom an ($1$) oder Strom aus ($0$). Ein einzelnes Zeichen heißt Bit (Binary Digit).

1 Bit 2 Zustände: $0$ oder $1$
Formel: $2^1 = 2$
2 Bits 4 Zustände: $00, 01, 10, 11$
Formel: $2^2 = 4$
1 Byte = 8 Bits (Oktett) 256 Zustände: $00000000_2$ bis $11111111_2$
Formel: $2^8 = 256$ ($0$ bis $255$)
Die 4-Bit-Wertetafel von 0 bis 15 (Zum schnellen Ablesen):
0: 0000 | 1: 0001 | 2: 0010 | 3: 0011 | 4: 0100 | 5: 0101 | 6: 0110 | 7: 0111
8: 1000 | 9: 1001 | 10: 1010 | 11: 1011 | 12: 1100 | 13: 1101 | 14: 1110 | 15: 1111
2 Die 8-Bit-Stellenwerttafel (Binär $\to$ Dezimal)

Im Dualsystem (Basis 2) verdoppelt sich der Stellenwert bei jedem Schritt nach links ($2^0=1, 2^1=2, 2^2=4, \dots$):

Zweierpotenz $2^7$ $2^6$ $2^5$ $2^4$ $2^3$ $2^2$ $2^1$ $2^0$ Dezimalwert
Stellenwert: 128 64 32 16 8 4 2 1 $\sum$ der gesetzten Bits
Beispiel 1: 1 1 0 0 0 0 0 0 $128 + 64 = \mathbf{192}$
Beispiel 2: 1 0 1 0 1 0 0 0 $128 + 32 + 8 = \mathbf{168}$
Beispiel 3: 0 0 0 0 1 0 1 0 $8 + 2 = \mathbf{10}$
Alle 8 Bits 1: 1 1 1 1 1 1 1 1 $128+64+32+16+8+4+2+1 = \mathbf{255}$
• Das Geheimnis der 255: Sind alle 8 Bits eines Bytes gesetzt ($11111111_2$), ergibt sich exakt $255$. Daher ist $255$ die Obergrenze eines IPv4-Oktetts!
3 Umrechnung Dezimal $\to$ Binär: Die zwei Verfahren
Methode A: Stellenwert-Zerlegung
Ideal für Kopfrechnen im Byte-Bereich ($0$ bis $255$).
  1. Prüfe Stellenwerte von links ($128, 64, 32, 16, 8, 4, 2, 1$).
  2. Passt der Wert? $\rightarrow$ Ja: $1$ setzen, Wert abziehen. $\rightarrow$ Nein: $0$ setzen.
  3. Mit dem Rest bis zur $1$ fortfahren.
Beispiel: $45_{10}$ umwandeln:
• Passt 128? Nein $\rightarrow$ 0 | Passt 64? Nein $\rightarrow$ 0
• Passt 32? Ja ($45 - 32 = 13$) $\rightarrow$ 1
• Passt 16? Nein $\rightarrow$ 0 | Passt 8? Ja ($13 - 8 = 5$) $\rightarrow$ 1
• Passt 4? Ja ($5 - 4 = 1$) $\rightarrow$ 1 | Passt 2? Nein $\rightarrow$ 0
• Passt 1? Ja ($1 - 1 = 0$) $\rightarrow$ 1
Ergebnis: $45_{10} = \mathbf{00101101_2}$
Methode B: Divisionsalgorithmus mit Rest
Universeller Algorithmus (auch für Großrechner & Programme).
  1. Teile die Zahl ganzzahlig durch 2.
  2. Notiere das Ergebnis und den Rest (0 oder 1).
  3. Wiederhole mit dem Ergebnis, bis dieses 0 ist.
  4. Lies die Reste von unten nach oben ab!
Beispiel: $168_{10}$ umwandeln:
$168 : 2 = 84 \text{ Rest: } \mathbf{0}$   (letzte Ziffer / LSB)
$84 : 2 = 42 \text{ Rest: } \mathbf{0}$
$42 : 2 = 21 \text{ Rest: } \mathbf{0}$
$21 : 2 = 10 \text{ Rest: } \mathbf{1}$
$10 : 2 = 5 \enspace\; \text{Rest: } \mathbf{0}$
$5 : 2 = 2 \enspace\; \text{Rest: } \mathbf{1}$
$2 : 2 = 1 \enspace\; \text{Rest: } \mathbf{0}$
$1 : 2 = 0 \enspace\; \text{Rest: } \mathbf{1}$   (erste Ziffer / MSB)
↑ Von unten nach oben: $\mathbf{10101000_2}$

4 Die Brücke zu IPv4: Warum Rechner Binärzahlen sehen

Für Menschen schreiben wir IPv4-Adressen in Dotted-Decimal-Notation (z. B. 192.168.0.10). Im Netzwerkchip existiert nur eine 32-Bit-Folge ($4 \times 8\text{ Bit}$):

Oktett 1. Oktett (8 Bit) 2. Oktett (8 Bit) 3. Oktett (8 Bit) 4. Oktett (8 Bit)
IP (Dezimal): 192 168 0 10
IP (Binär): 11000000 10101000 00000000 00001010
Maske (Dezimal): 255 255 255 0
Maske (Binär): 11111111 11111111 11111111 00000000
Bedeutung: 24 Einsen = NETZWERKTEIL (Gemeinsame Straße) 8 Nullen = GERÄTETEIL
Netzwerkteil (Netz-ID):
Wo die Subnetzmaske eine $1$ hat, müssen die Bits aller Geräte im selben lokalen Netz vollständig übereinstimmen, um ohne Router direkt via Switch kommunizieren zu können.
Geräteteil (Host-ID) & Reservierungen:
$8\text{ Bit}$ Geräteteil $= 2^8 = 256$ Adressen ($0$ bis $255$).
• .0 = Netzadresse (Name des gesamten Netzes)
• .255 = Broadcast-Adresse (Rundruf an alle)
$\rightarrow$ Nutzbare Geräte: $256 - 2 = \mathbf{254\text{ Rechner}}$ (.1 bis .254).

Zusammenfassung: Binärzahlen & IPv4-Adressierung

  • Stellenwertsystem zur Basis 2: Die 8 Stellenwerte eines Bytes lauten von links nach rechts: $$\mathbf{128} \quad \mathbf{64} \quad \mathbf{32} \quad \mathbf{16} \quad \mathbf{8} \quad \mathbf{4} \quad \mathbf{2} \quad \mathbf{1}$$
  • Die Summe 255: $11111111_2 = 128 + 64 + 32 + 16 + 8 + 4 + 2 + 1 = \mathbf{255}$. Mit 8 Bit lassen sich $2^8 = 256$ Zahlenwerte darstellen ($0$ bis $255$).
  • Divisionsalgorithmus: Zahl fortlaufend ganzzahlig durch 2 dividieren; die Reste ($0$ oder $1$) von unten nach oben gelesen ergeben die Binärzahl.
  • IPv4 & Subnetzmaske: Eine IPv4-Adresse besteht aus $4 \times 8 = 32\text{ Bit}$. Die Subnetzmaske (z. B. $255.255.255.0$ bzw. $/24$) trennt bitweise den Netzwerkteil (Einsen) vom Geräteteil (Nullen).
5 Selbsttest & Übungsaufgaben
Aufgabe 1 (Binär $\to$ Dezimal): Wandle die Binärzahl $11001010_2$ mithilfe der Stellenwerttafel in eine Dezimalzahl um.
Rechnung: $128 + 64 + 0 + 0 + 8 + 0 + 2 + 0 = \mathbf{202}_{10}$.
Aufgabe 2 (Dezimal $\to$ Binär): Wandle $77_{10}$ mit dem Divisionsalgorithmus mit Rest in eine Binärzahl um.
$77 : 2 = 38\text{ R }1$ | $38 : 2 = 19\text{ R }0$ | $19 : 2 = 9\text{ R }1$ | $9 : 2 = 4\text{ R }1$ | $4 : 2 = 2\text{ R }0$ | $2 : 2 = 1\text{ R }0$ | $1 : 2 = 0\text{ R }1$
Von unten nach oben: $\mathbf{1001101_2}$ (als 8-Bit-Byte: $\mathbf{01001101_2}$). Probe: $64 + 8 + 4 + 1 = 77$.
Aufgabe 3 (Netzwerk-Check): PC A: 192.168.2.15, PC B: 192.168.2.80, PC C: 192.168.3.15. Maske: 255.255.255.0. Wer kann wen direkt anpingen?
PC A und PC B können sich direkt anpingen (Netzwerkteil 192.168.2 identisch). PC C liegt im Netz 192.168.3 und ist ohne Router unerreichbar!
Aufgabe 4 (Denkfalle): Warum darf man im Netz 192.168.0.0 / 24 keinem PC die IP 192.168.0.255 geben?
Weil .255 (alle Hostbits $1$) die Broadcast-Adresse ist. Pakete an diese IP gehen an alle Rechner im Netz – sie darf keinem Einzelgerät fest zugewiesen werden.
